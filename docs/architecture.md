# Meridian Vendor Assessment Architecture

## Overview

Evidence-driven, deterministic third-party vendor risk classification pipeline.

```
Input CSV / Future UI
        ↓
Vendor Loader
        ↓
Vendor Validation
        ↓
Criticality Engine
        ↓
Assessment Scope Engine
        ↓
Structured Assessment Result
```

---

## Core Components

### Data Models (`src/meridian_assessment/models/`)
- `Vendor` — Immutable Pydantic model enforcing validation on required fields, domains, and the 5 criticality dimensions.
- `CriticalityAssessment` — Complete result payload with score, tier, depth, per-criterion breakdown, and reasoning.
- `AssessmentScope` — Scope boundaries and focus areas for investigation stages.
- `CriticalityConfig` — Validated scoring weights, severity scales, tier thresholds, and reasoning templates.

### Ingestion Layer (`src/meridian_assessment/ingestion/`)
- `BaseVendorLoader` — Abstract base allowing future loaders (API, database, JSON).
- `CSVVendorLoader` — CSV parsing with header normalization, duplicate ID rejection, and row error aggregation.

### Scoring Engines (`src/meridian_assessment/services/`)
- `CriticalityEngine` — Deterministic weighted scoring from `config/criticality.yaml`.
- `ScopingEngine` — Maps criticality tiers to assessment scope definitions.
- `AssessmentPipeline` — Orchestrates batch runs and JSON export.

### OSINT Interface (`src/meridian_assessment/osint/`)
- `BaseOSINTAssessment` — Abstract contract for future investigation engines. Accepts `Vendor`, `CriticalityTier`, and `AssessmentScope`.
- `OSINTAssessmentPlaceholder` — Returns explicit pending status until investigation engine is implemented.

## Scoring

Criticality score = Σ(criterion_score × criterion_weight)

### Weights
| Criterion | Weight |
|---|---|
| data_sensitivity | 0.25 |
| payment_flows | 0.20 |
| regulatory_exposure | 0.20 |
| operational_dependency | 0.20 |
| customer_data_volume | 0.15 |

### Tier Thresholds (inclusive lower bounds)
| Tier | Min Score | Depth |
|---|---|---|
| TIER_1 | 3.5 | COMPREHENSIVE |
| TIER_2 | 2.0 | TARGETED |
| TIER_3 | 0.0 | LIGHTWEIGHT |

### Explainability
Any criterion scoring ≥ 2.5 generates a human-readable justification in `reasoning[]`. All reasoning is derived from the scoring engine, not generated by an LLM.
